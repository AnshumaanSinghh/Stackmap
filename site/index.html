Everything your system talks to, with receipts

The real architecture lives in manifests, compose files, env templates, infrastructure code and imports. Stackmap reads all of it, so the map matches the code you ship today.

Every box has a receipt

Click a database and see every service that uses it, through which ORM, with the import lines and a link to them on GitHub. AI-drawn diagrams guess; Stackmap only draws what it can prove.

$ npx stackmap-cli why stripe

A README diagram that never goes stale

Keep a Mermaid diagram between two markers in your README. GitHub renders it natively, and CI fails when the code and the diagram disagree.

$ npx stackmap-cli readme --check

Architecture review on every pull request

The GitHub Action comments when a pull request adds a database, a service-to-service call or a new third-party API, with a diagram of just the change.

- uses: AnshumaanSinghh/Stackmap@v1

Rules your CI enforces

"Frontends never touch the database." "Only the API calls AI providers." Write it once in .stackmap.json; violations are annotated on the line that caused them.

{ "deny": "kind:app -> category:database" }

A map for your AI agent

An MCP server gives Claude Code, Cursor and other agents the system's shape before they edit it: what uses what, what breaks if it changes.

$ claude mcp add stackmap -- npx -y stackmap-cli mcp

How it works

Deterministic static analysis. Same code in, same map out.

Find the units

Every folder with a manifest (package.json, pyproject.toml, go.mod, Cargo.toml, Gemfile, pom.xml ...) is an app, service, worker or library.

Read the code once

Imports, env vars read and API hosts called, in nine languages. Tests, scripts and tool config are skipped.

Match the catalog

500+ technologies, each name verified against its registry: SDKs, drivers, Docker images, env vars, hosts and Terraform types.

Read the infrastructure

docker-compose, Kubernetes, Terraform, Wrangler, Render, ORM config and .env.example files wire the boxes together.
